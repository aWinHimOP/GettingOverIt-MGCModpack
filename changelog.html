1.28.0-beta.9 正式频道 · 2026-11-14

beta.8 只把「主题压暗」这条主干接上了，这版把剩下的边角补完，并给圆角组件加了一道防闪退的兜底。

主题适配补全

  • 社区页列表行：行底色从 Image 换成 RoundedRect 后，「已下载」的蓝色标记取不到组件，直接失效；现在按「谁在画就找谁」解析（Image / RoundedRect 都认）。
  • Mod 列表：选中高亮 / 恢复默认底色同样改成适配层，RoundedRect 行也能正常高亮。

圆角组件 NaN 兜底

布局一旦算出 NaN/Inf 尺寸，RoundedRect 会把 NaN 顶点提交给 GPU —— 表现就是花屏、卡死或直接闪退。现在检测到脏尺寸就跳过这一帧不画，宁可一帧空白也不提交坏网格。

已知问题

「切到社区页卡死闪退」这条还在查，本版未能确认根因（用户设备上的会话日志还没拿到）。如果仍然复现，请按群里的说明导出「问题复现报告」发给我们。

1.28.0-beta.8 正式频道 · 2026-11-14

这次跟上用户重做的整套界面。新 prefab 把大量「底图 Image」换成了 RoundedRect（圆角组件），还有一批面板干脆不再挂 Image。

现象：换新 UI 后主题染色、选中高亮、浅色底压暗全部失效

根因：Modpack 里所有取颜色 / 染色 / 压暗 / 设不透明的代码都是 GetComponent<Image>()。新 prefab 里这些节点挂的是 RoundedRect（打包时烘成 MGCScriptShell，运行时由 ShellBinder 还原），取 Image 拿到 null —— 不报错，只是**什么都没发生**：深色主题下面板仍是一片白、侧栏选中没高亮、设置条目点中没反应。

修法：新增一层 UIGraphic 适配器 —— 谁在画就找谁：Image → RawImage → RoundedRect → Text。旧的 Image 路径行为完全不变，只有 Image 缺失时才落到 RoundedRect（SetFill）。主题的「浅色底压暗」「面板不透明化」「按底图亮度选文字色」、设置页档位高亮、MGC 设置条目的选中底色，全部改走这层。

资源

主界面资源包 bundle/ui_mainmenu.unity3d 换成本次新构建（1,249,526 B）。其余 bundle 未变。

1.28.0-beta.7 正式频道 · 2026-11-14

beta.6 修掉了「进度归零」，真机日志又暴露出两个新问题：一处把好数据当成坏数据扔掉，一处会吃满内存。

「续传数据超出总大小」——本来是对的包，被当成坏包删了

现象：下载器日志反复出现 续传数据超出总大小（130827 > 127952），已删除 .part，进度条回到 0，重试四次后报失败。

根因：索引里记录的体积（127952）和服务器上真实文件的体积（130827）对不上。分块请求比文件还大时，服务器会把整份内容回给我们，于是「已收字节」超过「期望大小」；旧逻辑把这种超出当成数据损坏，直接删掉重来——可数据本身是好的，只是索引里的数字过时了。

修法：超出时不再删，改为以实际大小为准继续走收尾；真正的判据交给 sha256 校验（对不上才删）。体积只是提示，校验和才是门。

下载时整包读进内存 → 卡顿、闪退

修法：「整包单请求」这条兜底路径现在只对 4MB 以下的包开放；40MB 的地图包一律走 128KB 分块（服务端支持分段，实测可分块完整下完并校验通过），避免一次性把整包读进内存。地图包各平台的低内存机型不会再因为下载而闪退。

1.28.0-beta.6 正式频道 · 2026-11-14

上一版只把下载地址排对了，但「进度到 99% 又从头重下」是另一段逻辑的问题——这一版修掉它。

下载进度快满时反复归零

现象：地图包 / 模组包下到 99% 左右突然重新从 0% 开始，来回几次后就报失败。

根因：下载器里有一段「这台设备对非 0 起点的断点续传会卡死，所以退回整包单请求」的兜底逻辑。问题在于它的判断条件是「已有数据就退回整包」——可在一轮下载中途，第一块 128KB 落盘后就已经算「已有数据」了。于是每下完一块就删掉临时文件、从 0 重新拉；整包拉到 99% 一断，重试时又因为同样条件再删一次，进度就这样反复归零。

修法：整包模式改成只作兜底——只有断点续传连续失败两次（说明这条链路确实对非 0 起点 Range 不友好）才切换，且本次下载内不再切回；正常情况下按 128KB 分块续传，进度只前进不后退。另外重试间隔改成递增（1s / 2s / 3s，上限 6s），不再固定 1 秒连撞同一个瞬时故障。

实测：静默拉取 40MB 官方地图包，分块 318 秒完成，sha256 与索引一致（d6e42b54394f），说明服务端文件与索引是对得上的，问题纯在客户端这段重试逻辑。

1.28.0-beta.5 正式频道 · 2026-11-14

这一版只改了一样东西，但它是玩家在资源页第一眼看到的那行字：官方 Mod 包的介绍恢复了原文。

官方包描述恢复成「MGCMopdack默认的Mod整合包，集合了大部分常见Mod」

做了什么：官方包升级到 1.2.5，包内 manifest.json 的 description 恢复成最初那句介绍；站点资源页与游戏内社区页显示的都是这一句。为什么：前几版把介绍写成了「MGCModpack 正式频道版」，等于拿版本口号替换了原本的说明文字——资源页是给玩家挑包看的，介绍要说明「这是什么」，不是「这是哪个频道」。

顺带修掉的根因：站点生成 index.json 时，包的名称/作者/介绍只从「无版本号目录下那份包」（也就是最老的 1.2.0）里读，所以之后无论新包 manifest 写什么，页面上都停在旧文案。现在改成读最高版本的 manifest，改包里的文字、重新生成索引就会同步。

1.28.0-beta.4 正式频道 · 2026-11-14

两处「看起来莫名其妙失败」的问题，根因都在客户端：一个是下载，一个是报告器导出格式。

资源页下载老是「重试三次都下不来」

做了什么：下载候选地址里，把索引给出的真实路径排到第一位；新结构路径只当兜底。重试次数 2 次 → 3 次，等待改成递增（1s / 2s / 3s，上限 6s）。为什么：旧逻辑每次下载都先试一个仓库里根本不存在的地址（<类型>/<名字>/<版本>/文件名，实际结构是 …/versions/<版本>/），等于先把重试次数耗在一个必然 404 的地址上，网络一抖整轮就失败。

问题复现报告：固定导出成压缩包

做了什么：「导出报告」现在恒定生成一个 .zip（报告正文 + 截图 + 最近日志 + 配置 + 环境信息），并移除了调试页里那个能切成纯文本的开关。为什么：一次现场要带的东西不止正文，纯 txt 只能装文字，玩家得一个一个找文件发过来；压缩包一次给全，也不会因为旧配置残留而退回 txt。

1.28.0-beta.3 正式频道 · 2026-11-14

这一版加了一个给作者看的「问题复现报告」：遇到 bug 不用再手打一堆环境信息，点一下导出 zip 发过来就行。

问题复现报告：调试页左侧顶部开关 + 一键导出 zip

做了什么：调试页（设置 → 调试）左侧顶部新增「问题复现报告」开关，默认关闭；开启后可以导出 .zip，里面包含：报告（markdown）、截图、游戏日志、配置、环境信息（系统/显卡/内存/版本等）。把 zip 发给作者即可排查。为什么：真机上出的问题，靠文字描述经常缺关键信息，来回问好几轮；把现场一次性打包，能省掉一半沟通成本。

开销：默认关闭，不开启完全无感；开启后每帧约 0.12 ms（真机 6 项验证实测稳态值），对 60fps（16.7ms/帧）来说基本可以忽略。

官方包 1.2.4 / dll 同步更新

做了什么：dll 更新到 627,200 B / c6df9d71…（含 zip 导出、SystemProbe 无障碍探测、原始触摸采集、启动期汇总、ModpackState 双路径、主题冻结开关默认关）；官方包 1.2.4（20 个 mod，含性能优化、默认关闭）。为什么：报告器需要读这些新数据源，旧 dll 导出的信息不全。

1.28.0-beta.2 正式频道 · 2026-11-14

beta.1 → beta.2 只换了一样东西：官方包。程序本体（dll）没动。

官方包换成 1.2.3：性能优化 mod 回到正式频道（20 个 mod）

做了什么：官方 MGCModpack.modpack 升级到 1.2.3，共 20 个 mod，重新包含「性能优化」mod（默认关闭，在 设置 → 性能优化 里开启）；AIGOI / AIRL 仍然不在官方包里。为什么：beta.1 为了瘦身把性能优化一起拿掉了，实测低配机（0.3 档 +11.5% fps）挺需要它；现在改成「默认关、想要自己开」，既不影响默认体验，也不需要另装包。

dll 不变：四排统计字号统一沿用

做了什么：程序本体与 beta.1 完全一致（同一份 dll，sha256 14c843a9…）。为什么：这一版只调整官方包组成，没有再改客户端代码，减少回归面。

1.28.0-beta.1 正式频道 · 2026-11-13

第一个正式版。这一版只做两件事：把官方包收干净，把主面板那排数字收进面板里。

官方包移除 AIGOI，只剩 19 个 mod

做了什么：官方 MGCModpack.modpack 不再包含 AIGOI（本机推理 + 进化的实验 mod），包内 mod 数量从 20 降到 19。为什么：AIGOI 是实验性质、吃性能、普通玩家用不到；放进正式包既占体积也容易让人误开。想玩的仍然可以单独装，不影响官方包。

主面板四排统计：字号统一，不再超出面板

做了什么：主面板四排统计（游玩时长 / 重开次数 / 通关次数 / 今日最佳）现在会各自算出「不超出本排宽度」的最大字号，再取四者里最小的那个，四排统一用同一个字号；实在放不下就四排一起改成两行。为什么：游玩时长可以很长（比如 100 小时），旧版按 34pt 画会顶穿面板——实测文字右边界 x1888，面板右边界 x1862，超出 26px；统一 31pt 后右边界 x1811，面板内还剩 51px。只缩一排会让四排看着不齐，所以一起改。

测试频道在开发期间跑过 alpha.236 / 237 / 238（公告修复、横屏实验）。横屏方案依赖系统层、已撤掉，正式频道用户直接从 236 拿到 beta.1，不受影响。

1.28.0 开发期间 alpha.232 ~ 238 · 测试频道

这一段不在正式频道的版本号里，但功能都进了 beta.1。

下载：多源 + 停滞检测 + 按文件预算

做了什么：下载改成 Pages → raw 多源，单个文件卡住就判「停滞」并换源，预算按文件分配而不是整包一刀切。效果：最慢的面板大图 panel-placeholder 从 67.33s → 9.73s（6.9×）。改之前一次全量同步 114.5s，其中 2.4MB 的这一张图就占了 67.3s（60s 超时 + 7s 重试成功）——用户看到的「进度停住」就是它。

加载页：固定区域、不裁切、显示速度

做了什么：加载页改成固定区域布局（内容变化不再抖），右侧统计区不再被裁掉，补上实时速度和进度显示。为什么：原来边下边重排，数字跳来跳去；右侧统计在某些分辨率下直接被切掉一半。

公告：自动弹出规则 + 首启按钮 + 客户端补拉

做了什么：公告弹出有了明确规则——内容哈希变了 / 跨天 / 打开菜单 / 首次进游戏，四种情况各弹一次，弹过就记住（日期 + 内容指纹）。首启时顶栏「公告」按钮不再依赖内容是否拉到，先放按钮再填内容；万一首启下载预算被资源包吃光，客户端会自己补拉 config/announcements.json 并原子写盘。为什么：原来公告没拉到就连按钮都没有，玩家以为没有公告；首启预算耗尽时公告会整段跳过。

落盘：严格写入隔离

做了什么：mod 只能写自己名下 Mods/<模组名>/，越界写直接被拒绝并记一条审计日志；旧路径（MGCModpack/AIGOI、MGCModpack/存档）只允许读、不许写。存档、AIGOI 权重、性能配置各自迁到 Mods/存档/、Mods/AIGOI/、Mods/PerfMod/。为什么：之前 mod 到处写文件，卸载/迁移时容易互相覆盖，也说不清是谁写的。

工具链 mgcpush

发布流程本身也重写了，和玩家无关，但决定了这个站点的更新速度。

做了什么：新增 mgcpush（命令行 + 图形界面）统管站点发布：打包整版本快照、逐文件 sha256 锁文件、干跑先看计划、删远端历史目录前必须有本地快照（安全门）、回滚只动频道指针、一条命令把整站恢复到某个快照。为什么：以前靠手工改 index/上传，出过「索引里有、线上没有 → 设备同步 404」和「回滚了指针但 pin 没退」的事故。现在每次发布前先 dry-run 打印「将上传/将删除/安全门/稳定版断言」，稳定版目录 sha 不变才允许发。
